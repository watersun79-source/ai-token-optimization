예약에 남아 있던 “없는 프로젝트 컨텍스트 설정 도구를 복구하기 전까지 대기” 전제가 반복 작업의 원인이었다. 이를 현재 도구 목록과 실제 프로젝트 신원을 확인하고 최신 색인의 미완료 작업을 선택하는 지침으로 바꿨다. 도구가 접근/컨텍스트 오류를 내면 우회하지 않고 가능한 독립 작업으로 전환하도록 했다. 제목·일정·활성 상태는 바꾸지 않았고 예약을 새로 만들지 않았다. 비용·main·운영 플로우 보호 조건을 보존했다.

기존 ChatGPT/Codex 지침과 예약 프롬프트는 로컬 work/에 백업했다. 사용자의 불필요한 개인 설정 내용은 공개 기록으로 옮기지 않았다.

Windows의 대소문자 구분 없는 파일 경로에서 짧은 대문자 안내문이 자기 자신을 가리킬 수 있어, 두 프로토콜 이름은 현재 절차의 완전히 같은 본문으로 유지했다. 내용 갱신 시 양쪽을 함께 저장·재조회하는 규칙도 추가했다. GitHub의 호환 링크는 유지했고, 저장소 전체의 Windows 체크아웃을 검증했다고 주장하지 않는다. 이 추가 변경의 문자열·blob 일치는 root와 별도 에이전트가 각각 재조회해 확인했다. 별도 에이전트는 두 본문 3,935 UTF-16 단위와 blob 일치, 기존 실행·보호 절차의 문자열 보존을 확인했다.

## 분리된 문맥 복원 시험 — 6/6

과거 대화를 전달하지 않은 별도 에이전트에 정규 색인 시작 주소만 줬다. 에이전트는 연결된 프로토콜·최신 보고서·지침과 Slack 기록을 직접 읽어 다음 사실을 복원했다.

1. PR #1 → #4 사용자 승인 병합, 최종 main `297d1d2d52e213e0b3c93c93d74e322fb11e744b` 복원.
2. Python23 + JS32 + guard72 = 127/127, 최종 main CI `39262028914` 성공 복원.
3. 두 AI 플로우 DISABLED·임의 재활성화 금지와 Slack ENABLED 결정을 복원하고, 과거 3개 활성 상태가 대체됐음을 구분.
4. 기존 매시간 예약 보존과 운영 관찰 시점 22:28~22:29를 구분.
5. 대문자 호환 문서가 같은 시작점으로 연결되는지 직접 읽고, 정규/표시 지침 문자열·blob 동일 및 본문 1,133 단위를 직접 비교.
6. 외부 기록 복원 시험과 모든 새 채팅의 자동 실행 보장을 구분하고, 공급자 API 금지·운영 게시/청구/경합 연구 미검증을 정확히 복원.

이 시험은 수동으로 전체 과거 대화를 복사하지 않고 출처에서 상태를 되찾는 경로를 검증한다. 모든 ChatGPT 새 채팅에서 자동으로 도구 호출이 시작되는지까지 증명하는 시험은 아니다.

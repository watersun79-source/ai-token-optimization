# AI BOT v8.1 adaptive 4/8/16 parallel read isolation (2026-10-24)

- GitHub isolated runtime only; existing production minute-00 ChatGPT schedule, GitHub minute-15 cron, main, Activepieces, Slack settings, permissions and billing are unchanged.
- Old `v81_speed_orchestrator.batch_read` (4-worker maximum) delegates to `v81_adaptive_parallel.safe_batch_read`, which supports 1-16 local worker threads for exact-key read-only tasks. Default=4.
- `AdaptiveParallel` opt-in `ceiling=16` promotes 4→8→16 only after TWO successive fully-saturated successful batches at each tier, and reports actual tier used. `ceiling=4` is default when provider-specific limits are unknown. Do not automatically use 16 against Slack/GitHub API without separate app permission and quota assessment.
- Failure automatically reduces tier (16→8, 8→4; 429/rate limit and 401/403→4), *does not retry failed batch*, and preserves exception as fail-closed `AdaptiveReadError`; provider's Retry-After, explicit authorization and freshness of inputs must be checked before a NEW invocation. No bypass.
- The runner-local benchmark uses 32 distinct I/O-shaped keys, 8ms **synthetic sleep per key**, 4/8/16 threads, real hosted Linux wall clock, measured peak simultaneous tasks, actual `os.cpu_count`, process RSS and `/proc/meminfo`. Real GitHub/Slack API 16-request tolerance, connector concurrency and quotas are **NOT** verified by that offline test.
- Actual provider test via connected GitHub plugin was read-only: four distinct calls succeeded in 1049 ms; eight distinct calls succeeded in 2229 ms (different workloads; not A/B speedup). The ChatGPT connector doesn't surface remaining API quota headers; previous attempt at 16 calls in one orchestration exceeded the client tool-call limit and did not prove a GitHub 16-request quota failure. No bulk Slack load testing.
- Official docs: https://docs.github.com/en/actions/reference/runners/github-hosted-runners (public ubuntu-latest: 4 CPU / 16GB / 14GB SSD); https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api (secondary global 100 concurrent, account quotas and 403/429 subject to conditions); https://docs.slack.dev/apis/web-api/rate-limits/ (method/workspace-specific tiers and Retry-After).
- `max_workers=16` means up to 16 I/O-bound threads, **not** 16 CPU cores, 16 AI models, 16 API calls guaranteed, or proof of native unattended ChatGPT success. For CPU-bound workloads on 4 vCPU runner, test separately and avoid oversubscribing.

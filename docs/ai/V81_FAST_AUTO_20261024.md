# AI BOT v8.1 FAST auto-tune for isolated local workloads (2026-10-24)

Goal: opt in to measured 4–256 adaptive local concurrency instead of selecting the highest available tier by default.

The existing FAST64/FAST128/FAST256 controllers and live integrations are left unchanged. The new `v81_fast_auto.AdaptiveFast` is **local-only**, explicitly opt-in. It consumes two separately measured, complete 256-task, 0-error FAST256 benchmark profiles with 64/128/256 samples in the same test conditions. It requires >=5% improvement at both sources for each promotion; otherwise retains the smaller tested tier. CPU hashing and unknown workloads stay at 4 (actual CPU-count based optimization not proven). If a profile is absent or invalid it stays at 4; no synthetic benchmark is silently treated as real GitHub/Slack provider permission.

Existing local thread controller staged ramp-up, response dedup, memory and latency-triggered reduction, fail-closed no-retry and 429/access backoff are retained. The automatic policy never grants native ChatGPT parallel processing nor modifies ChatGPT reservations, GitHub main/hourly :15 cron, or any production app. Real API connector concurrency remains <=4 and only within independently allowed quotas.

# AI BOT v8.1 — 실험용 대체 18개 역할 (82 + 18)

## 원칙

- 원본 100개 규칙, `catalog.json`, 기존 CI 통과 이력, 예약·main·`:15` cron·Activepieces·Slack·비밀 ZIP는 바꾸지 않는다.
- 원본 `L06–L10`, `A07–A09`, `E01–E10`은 **ChatGPT native 예약의 출처 인증 게이트**이므로 제거할 수 없으며, 공식 원장 부재 시 여전히 `UNVERIFIED`다.
- 별도 **실험용 대체 프로필**에서 82개 기존 오프라인 검사 슬롯과 GitHub 오프라인 감사용 신규 `V01–V18` 슬롯을 결합해 총 100개 역할을 구성한다. `V` 규칙은 **다른 검증 목적**이고 원본 게이트를 통과한 것과 같지 않다.
- 같은 원래 슬롯 `L/A/E`를 `original_slot`에 기록해 10영역×10개의 원래 슬롯 배치를 추적하되, 새 역할 ID는 `V01–V18`로 구분한다. 기존 소스 카탈로그는 수정하지 않는다.
- 새 역할의 PASS는 **제공된 GitHub 실행 데이터와 원시 로그의 구조적 일관성**이다. 입력 JSON은 서명되지 않았으며 프로그램만으로 GitHub 공급자 출처를 증명하지 않는다. ChatGPT 예약 성공은 별도의 공식 per-run 원장과 동일회차 호출 근거가 있어야 한다.

## 사용 (로컬 전용)

```bash
cd experiments/r16-bot-runtime
python3 -m unittest -v test_v81_verifiable_18
python3 v81_verifiable_18.py --catalog catalog.json  # 18회 UNVERIFIED: 진짜 입력 없이 PASS 불가
python3 v81_verifiable_18.py --snapshot /path/to/read-only-github-snapshot.json --catalog catalog.json
```

`snapshot` JSON 필드: `run`(GitHub API), `job`(같은 run의 Job API), `raw_job_log`(같은 job의 로그 텍스트), `main_sha`(별도 원격 HEAD 조회), `inferred_slot_utc`(cron에서 추정, 공식 run 예정시각 아님). 출처 원본 조회는 이 로컬 코드 외부에서 사용자 허가를 받은 연결 도구로 수행하며, 가능하면 저장하지 않고 전달한다.

## 완료 판정

- **로컬**: 단위검사, 각 규칙의 거부 테스트, 원본 미변경 테스트 완료 여부를 기록.
- **격리 브랜치**: 새 소스·테스트·문서를 커밋하고 공식 push CI의 `fast-audit`/`full-regression` run 및 원시 로그를 확인한 경우에만 원격 검증 PASS.
- **실제 provider**: 위 로컬 코드가 구조 검증 PASS를 출력해도 공식 ChatGPT native 예약의 18개 출처 게이트는 UNVERIFIED 그대로. 외부 AI·유료 API 호출 0.

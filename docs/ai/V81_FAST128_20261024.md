# AI BOT v8.1 FAST128 option — isolated only (2026-10-24)

- Existing `Fast64` defaults to a **64 local-worker ceiling** and existing live GitHub/Slack connector policy remains **4 concurrent calls pending independent quota verification**.
- New `Fast128` is an explicit **local offline-only opt-in**. It promotes 4→8→16→32→64→128 only after two successful saturated batches per level; comparable latency repeatedly degrading by >10%, or RSS threshold, causes an irreversible tier drop in the current controller. 429 / access denial returns to 4; failures are never auto-retried.
- Same hosted-run comparison tests 128 distinct tasks under 1ms and 8ms synthetic waiting and local SHA256 CPU activity, 64 vs 128 threads. These are actual hosted CPU/clock measurements but **NOT live network throughput nor proof of provider API capacity**.
- No deployment, no main merge, no ChatGPT native scheduler changes, no :15 GitHub cron changes, no Slack/Activepieces changes, no purchases, no provider calls in the experiment. Original ZIP remains private.
- Safe recommendation: prefer 64 for long local I/O when 128's marginal gain is small; opt into 128 only for workload with repeatable wins and ample memory. Short CPU-bound tasks should stay near vCPU count.

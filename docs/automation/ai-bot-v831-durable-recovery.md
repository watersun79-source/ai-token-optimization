# AI BOT v8.3.1 · 재시작 후 작업 자동 복구 (격리 검증)

## 변경과 목표
- `tools/durable_queue_v831.py`는 Python 표준 라이브러리 `sqlite3`의 `BEGIN IMMEDIATE` 트랜잭션으로 작업을 원자적으로 선점한다.
- 처리 중 프로세스가 종료되면 작업 기록 `CLAIMED`와 임대 만료 시각을 디스크에 남긴다. 별도 프로세스가 다시 시작돼 `recover()` 또는 `claim()`을 호출하면 만료된 임대만 안전하게 재대기시킨다.
- 작업 ID 유일성 + SHA256 payload digest 비교, 새 임대 토큰 발행, 기존 임대 토큰 펜싱, heartbeat, 최대 시도 횟수와 DEAD 처리 제공.
- `tests/test_durable_queue_v831.py`의 15개 테스트에서 **실제 별도 Python 프로세스 종료 후 복구**, 독립 SQLite 연결의 원자적 경합, 재시도 제한, 자격 정보·미검증 작업 거부를 검증한다.
- 외부 네트워크·LLM·GitHub dispatch·Slack 호출은 코드에 없다.

## 반드시 구분할 것
- **재시작 후 복구 가능한 데이터 저장 로직**과 **항상 살아 있는 작업 실행기**는 다르다. 이 모듈은 실행기를 시작하거나 예약 등록·부팅 시 자동 실행·이벤트 구독을 하지 않는다.
- **영속 저장소 필요**: 이 SQLite 파일은 재시작 후 동일한 디스크에 남아 있어야 한다. Render Free 웹 서비스의 로컬 파일은 일시적이므로 이 모듈을 Render Free 로컬 디스크에 배포해 영속 복구를 주장하지 않는다.
- **At-least-once** 작업 처리만 보장한다. 이전 임대가 만료된 뒤 동일 외부 부작용이 두 번 수행될 수 있으니 실제 서비스에서는 작업 ID 기반 대상 시스템의 멱등성 키·트랜잭션 아웃박스가 별도로 필요하다.
- 외부 웹훅 인증, Activepieces의 작업 큐와 실제 원자적 D1 claim 연동, 실시간 대시보드 구독, 24시간 가동 SLA, 외부 API 비용·크레딧은 아직 확인되지 않았다.
- 기존 Activepieces 표 `TEST ONLY · v8.3 Durable Job Ledger`와 비활성 이벤트 플로우는 수정하지 않는다. 새 SQLite 코드는 **격리 구현**이며 외부 저장소와 직접 동기화하지 않는다.

## 승격 게이트
1. GitHub Draft PR의 공식 CI `python -m unittest discover -s tests -v`에서 15개 회귀 테스트+기존 53개 통과 확인.
2. 지속 디스크 또는 관리형 영속 DB + 원자적 임대 API 마련 후 별도 격리 환경에서 종료/재시작 실운영과 동시 선점 검증.
3. 기존 보호 조건을 어기지 않는 인증된 이벤트 접수, 만료 임대 회수 스케줄, 백프레셔, 실행별 provenance, 비용 한도 확인.
4. 위 검증 전 `main` 병합, 기존 정각 예약·시간별 고정 감사 설정, Activepieces 운영 변경, 유료 배포 금지.
